# Collapse remedies — paper survey vs. Thinker code

Sources fetched (LaTeX, `~/.cache/nanochat/knowledge/<id>/`): 2606.24898 ✓, 2606.29983 ✓, 2604.15259 ✓, 2606.18206 ✓, 2604.12946 ✓. All five available and read (abstract/intro/defs level given time budget).

## Per paper: mechanism → fix → our code

**2606.24898 Readout Blind Spot.** Dense per-loop CE only supervises the variables the readout exposes; if the readout is scale-invariant (RMSNorm/LayerNorm) while the pre-norm residual recurrence keeps accumulating scale, that scale drifts unboundedly (norms → 10^3–10^4) because loss never "sees" it. Fix: scale-visible readout or scale-removing recurrence.
→ Our code: `get_output` (core/thinker_model.py:240-256) reads `output_proj`/`probe_proj` directly off the raw post-residual latent slice (`latent[:, L:, :]`, set at core/thinker_model.py:226-227) — **no norm before readout**, so in our case CE *should* see raw scale. But `self.latent` fed back into the next `compute_step` (core/thinker_model.py:226, then re-entered at line 194/197) is **only normed transiently** (`latent = self.ln_1(latent)` is a local copy, line 197) — the stored recurrent state itself is never normalized outer-loop. So we have the opposite asymmetry: readout sees raw scale, but nothing bounds what accumulates in `self.latent` across n_step iterations — a plausible source of the input-independent runaway/collapse.

**2604.15259 Stability & Generalization in Looped Transformers.** Proves looped nets need (a) recall — conditioning each iterate on the original input — and (b) outer normalization on the loop state, together, to get fixed points that are reachable, input-dependent, and geometrically stable. Without both, fixed points are only countably many / collapse to input-independent attractors.
→ Our code: recall-like input access exists (cross-attn to `k_cache`/`v_cache` input slice every step, core/thinker_model.py:92-112, 201-205), but there is **no outer normalization wrapping the whole recurrent step** — only internal pre-norms `ln_1`/`ln_2` inside the block (lines 197, 223), not applied to the state that's carried to `t+1`. This is exactly the "recall without outer norm" regime the paper predicts is unstable/near-collapse.

**2606.18206 Fixed-Point Reasoners (FPRM).** Same diagnosis independently: looped depth causes a signal-propagation problem (halting postponed, magnitudes blow up); fix is pre-norm layers **plus residual scaling** (not just pre-norm) before using fixed-point convergence as a halting signal.
→ Our code: residual adds are unscaled (`latent = latent + self.mlpf(...)`, line 223) — no learned/fixed residual-scale factor. Also note lines 222-223 apply `mlpf` twice in a row (`attn = self.mlpf(attn)` then `self.mlpf(self.ln_2(attn))`) — looks like a bug independent of the papers, worth checking since it doubles the nonlinear branch depth per step.

**2604.12946 Parcae.** Traces looped-model instability (residual explosion, loss spikes) to large spectral norm of the *injection* parameters (the maps that write new content into the residual stream each loop). Fix: constrain injection spectral norm via a stable (negative-diagonal / discretized) parameterization.
→ Our code: the injection points are `attn_kv_memory` (core/thinker_model.py:20, 132-147, writing latent→memory every step) and `attn_sc` (line 21, writing latent updates every step) — both plain unconstrained `nn.Linear`, std-0.02 init (line 50), no spectral constraint. Under n_step iteration this is precisely Parcae's failure mode.

**2606.29983 Learned Stochastic Stopping.** Diagnoses OOD variance from a spurious length↔loop-count correlation, fixed by randomizing loop count at train time; already effectively covered by our ruled-out "n_step value" ablation — lowest relevance to the 0.3-0.5% collapse (this looks like a variance/generalization issue, not a collapse-to-near-zero issue).

## Ranked ablations (exact change, expected effect, cost)

1. **Add outer normalization on the carried latent state** (2604.15259 + 2606.24898): after line 226, replace `self.latent = latent[:, :L, :]` with `self.latent = self.ln_outer(latent[:, :L, :])` (new `nn.LayerNorm`, not `ln_1`/`ln_2` which are reused every step already). Expected: this is the single most-implicated missing ingredient across 3 of 5 papers — likely to move accuracy off the collapse floor if the failure is fixed-point degeneracy. Cost: trivial (one new LayerNorm, one line), full retrain needed to confirm.
2. **Fix the double-`mlpf` call** (lines 222-223): `attn = self.mlpf(attn)` then `latent + self.mlpf(self.ln_2(attn))` — should almost certainly be `attn_out = attn` (no mlp), then `latent = latent + self.mlpf(self.ln_2(attn))`, matching standard pre-norm block (attn residual, then separate mlp residual — currently missing the attention's own residual add entirely, since `latent` used in `add_latent` is pre-attention and the attn-only residual is skipped). Expected: could itself explain collapse (broken residual path around attention). Cost: trivial, 1-line fix, cheap to test in isolation before combining with #1.
3. **Bound/constrain the injection linears** (Parcae): apply spectral norm (`nn.utils.parametrizations.spectral_norm`) to `attn_kv_memory` and `attn_sc` (lines 19-21). Expected: reduces risk of exponential blow-up/collapse over many n_step iterations; secondary to #1/#2. Cost: low, wrap 2 Linear layers, retrain.
4. **Scale the residual updates** (FPRM): multiply the mlp/attn residual branches by a learned or fixed `1/sqrt(n_step)`-ish scale before adding, complementing #1. Expected: smaller effect alone, useful combined with outer norm. Cost: low.
5. **Add recall of the *original* input embedding at every step**, not just cache lookup (2604.15259's specific "recall" definition is re-injecting original input, not just being attend-able) — check whether `load_input` cache slice actually still contains the original untouched input embeddings at step n_step>1, or if cache/position slicing drifts. Cost: medium (needs tracing `extend_kv_from_cache`/`cache_input_length` logic), lower priority since memory-off was already ruled out.
