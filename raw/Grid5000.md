**How to Request GPU Instances with OAR**

Grid'5000 allows you to target specific GPU architectures or slice individual cards directly through OAR properties:

* **Request a single GPU of a specific model:**
  ```bash
  oarsub -I -l gpu=1 -p "gpu_model = 'A100'"
  ```
  *(On a multi-GPU node, this allocates fractional host RAM and cores proportionally to avoid idle resource lockup.)*

* **Reserve an entire multi-GPU node (e.g., for bare-metal OS deployment or `kadeploy`):**
  ```bash
  oarsub -I -p "gpu_count >= 4 and gpu_model = 'A100'"
  ```

* **Reserve on Rennes `abaca` queue specifically:**
  ```bash
  oarsub -I -q abaca -p "gpu_model = 'H100'"
  ```

# gemini response

Pour utiliser Grid'5000 efficacement et éviter les erreurs classiques (blocage de compte, pertes de calcul ou conflits de clés SSH), voici les règles et mécanismes essentiels à maîtriser :

**1. Configuration SSH et clé RSA**

* **Algorithme RSA sous OpenSSH récent :** Les versions récentes d'OpenSSH désactivent par défaut l'algorithme de signature `ssh-rsa` (SHA-1). Si votre clé RSA est rejetée lors de la connexion à `access.grid5000.fr`, ajoutez ces directives dans votre fichier `~/.ssh/config` local :
  ```ssh-config
  Host *.grid5000.fr
    HostkeyAlgorithms +ssh-rsa
    PubkeyAcceptedAlgorithms +ssh-rsa
    User jdomguia
    IdentityFile ~/.ssh/id_rsa
  ```
* **Rebond transparent (ProxyJump) :** Vous ne devez jamais lancer de calculs sur la machine d'accès (`access.grid5000.fr`). Vous sautez d'abord sur un site (ex. Rennes), puis sur un nœud. Pour vous connecter directement à un site sans taper de doubles commandes, configurez votre `~/.ssh/config` :
  ```ssh-config
  Host g5k
    User jdomguia
    Hostname access.grid5000.fr
    ForwardAgent yes

  Host *.g5k
    User jdomguia
    ProxyJump g5k
    ProxyCommand ssh -W $(basename %h .g5k):%p g5k
  ```
  *(Vous pourrez ainsi taper directement `ssh rennes.g5k`)*.

---

**2. Architecture d'accès et règle d'or**

* **Niveaux de machines :**
  1. `access.grid5000.fr` : Bastion uniquement (passerelle SSH). **Interdiction formelle de compiler ou calculer ici.**
  2. `frontend` du site (ex. `rennes.grid5000.fr`) : Gestion des jobs OAR, transferts de code, monitoring. Calculs légers autorisés, mais pas d'entraînement de modèle.
  3. `nœuds de calcul` (réservés via OAR) : Exécution réelle de vos scripts ML.

---

**3. Réservation de ressources avec OAR**

Tout accès à un GPU ou CPU passe par le gestionnaire de jobs **OAR** depuis le frontend d'un site :

* **Mode interactif (pour tester et debugger) :**
  ```bash
  # Réserver 1 GPU pendant 2 heures sur Rennes
  oarsub -I -l gpu=1,walltime=2:00:00 -p "gpu_model = 'A100'"
  ```
  Dès que le job démarre, un shell s'ouvre sur le nœud alloué.
* **Mode batch (expérimentations longues en arrière-plan) :**
  Créez un script bash `run.sh` et soumettez-le :
  ```bash
  oarsub -l gpu=1,walltime=8:00:00 ./run.sh
  ```
* **Nettoyage :** Si votre expérience se termine plus tôt que prévu, libérez les ressources pour les autres utilisateurs avec `oardel <job_id>`. Laisser tourner un job vide pénalise votre priorité de réservation (politique de fair-use).

---

**4. Stockage et persistance des données**

* **Home Directory (`/home/jdomguia`) :**
  * Partagé via NFS au sein d'un même site (accessible depuis le frontend et tous les nœuds de ce site).
  * **Non répliqué entre sites :** Les fichiers stockés sur `/home/jdomguia` à Rennes n'existent pas à Lyon ou Lille.
  * Quota par défaut limité (souvent ~100 Go). Ne l'utilisez pas pour les I/O intensives de datasets ML (le NFS ralentit les dataloaders PyTorch/TensorFlow).
* **Stockage temporaire local rapide (`/tmp` ou `/scratch`) :**
  * Situé directement sur le SSD/NVMe local du nœud réservé.
  * Recommandé : Copiez votre dataset compressé depuis le home vers `/tmp` au début du job, extrayez-le localement, puis réécrivez uniquement les checkpoints/poids finaux sur `/home` à la fin.
  * **Attention :** `/tmp` est automatiquement vidé dès que le job OAR prend fin.

---

**5. Environnement logiciel (Python & ML)**

* **Debian de base :** Les nœuds tournent sous une image Debian standard sans CUDA préinstallé dans le user space.
* **Bonnes pratiques :**
  * Utilisez **Miniconda / Mamba** installé dans votre `$HOME` pour configurer vos environnements PyTorch/GPU spécifiques.
  * Ou utilisez **Singularity / Apptainer** : compatible Docker sans droits root, idéal pour exécuter directement des conteneurs Nvidia PyTorch (`nvcr.io/nvidia/pytorch:...`).
  * Si vous avez besoin d'un OS sur-mesure ou des droits root complets pour des pilotes spécifiques, utilisez l'outil de déploiement d'images bare-metal de Grid'5000 (`kadeploy3`).

# gemini response

Pour éviter les suspensions de compte, les pertes de données ou les blocages administratifs sur Grid'5000, voici les pièges critiques à connaître :

**1. Sur le plan technique & bonnes pratiques opérationnelles**

* **Ne lancez jamais de calcul lourd sur les frontends :** Exécuter un script Python, un prétraitement lourd ou un entraînement sur `rennes.grid5000.fr` (au lieu d'un nœud alloué via OAR) déclenche des alertes automatiques et entraîne l'arrêt immédiat de vos processus par les administrateurs.
* **Le piège du `walltime` OAR :** Quand la durée réservée expire, OAR envoie un signal `SIGTERM` suivi rapidement d'un `SIGKILL`. Tout ce qui n'a pas été sauvegardé sur `/home` ou un stockage persistant est perdu, et le disque local `/tmp` du nœud est nettoyé. **Sauvegardez vos checkpoints régulièrement.**
* **I/O intensives sur NFS :** Entraîner un modèle de vision/NLP en lisant des millions de petits fichiers directement depuis votre `/home` sature le serveur NFS partagé du site, dégrade les performances de tous les chercheurs et fait ramer votre job. Copiez toujours vos archives sur `/tmp` ou le disque local du nœud avant de lancer l'entraînement.
* **Indépendance des sites :** Votre compte existe partout, mais vos données ne voyagent pas automatiquement. Si vous réservez un GPU à Lyon après avoir développé à Rennes, vous devrez transférer vos scripts et poids manuellement (via `rsync` ou `scp`).

---

**2. Sur le plan légal & sécurité**

* **Accès SSH strictement nominatif :** Votre compte est personnel. Partager vos clés SSH ou prêter votre accès à un tiers (même un étudiant ou collègue du CETIC) constitue une violation grave de la charte de sécurité RENATER/Inria et mène à la révocation immédiate du compte.
* **Types de calculs strictement interdits :**
  * Minage de cryptomonnaie (détecté quasi instantanément).
  * Scans réseau, attaques par déni de service, tentatives d'intrusion ou tests de vulnérabilités non autorisés.
  * Hébergement de services web publics permanents sans déclaration.
* **Données sensibles & RGPD :** Grid'5000 est une infrastructure de recherche expérimentale, non un cloud certifié HDS (données de santé) ou bancaire. Ne stockez pas de jeux de données contenant des données personnelles non anonymisées ou des secrets industriels.

---

**3. Sur le plan administratif & gestion du compte**

* **Comptes temporaires et revues annuelles :** Les comptes invités ou rattachés à des projets de recherche (comme l'équipe `wide`) ont une durée de validité limitée (généralement 1 an renouvelable). Surveillez vos emails institutionnels : si vous manquez la campagne de re-validation annuelle du parrain, le compte est verrouillé sans préavis.
* **Fair-use et réservation fantôme :** Réserver des nœuds GPU rares (comme des A100 ou H100) pour plusieurs jours sans exécuter de calculs réels (idle) pénalise votre priorité de réservation dans OAR et expose votre job à une annulation manuelle par l'équipe support. Libérez toujours vos ressources (`oardel`) dès la fin de votre run.
* **Obligation d'acknowledgement (remerciements) :** Si les calculs menés sur Grid'5000 aboutissent à des publications scientifiques, conférences ou rapports techniques, la charte impose d'inclure la mention légale de citation de Grid'5000 dans vos articles :
  > *"Experiments presented in this paper were carried out using the Grid'5000 testbed, supported by a scientific interest group hosted by Inria and including CNRS, RENATER and several Universities as well as other organizations (see [https://www.grid5000.fr](https://www.grid5000.fr))."*
